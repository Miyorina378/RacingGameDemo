# Spur-road fixes leave stacked-surface and layout lifecycle regressions

Latest fixes close live-road-side wall resolution, vertical wall overlap, first-run spur-only layout test drive, raced endpoint cleanup/stale-save unassignment, and closure-flag reversal. Banked main-road support still loses to an overlapping spur because arbitration uses centerline height; AI slope and grass classification also discard elevation. Retry drops the selected course, and editor selection state can disable Delete or delete an old spur point. **Watch for:** **confirmed, High** banked main/spur crossings can select the wrong support deck; **confirmed, Medium** AI slope and grass grip stay XZ-only; **confirmed, Medium** Retry drops the selected course; **confirmed, Medium** spur Delete state can target the wrong object.

**Verdict**: NEEDS_CHANGES

## High-level view

**Confirmed:** main-versus-spur support reads `yHint`, but represents the main candidate with centerline height. Final support comes from banked edge geometry, so arbitration can choose a spur while the car sits on the banked main surface.

**Confirmed:** player slope samples pass vehicle Y, but the AI wrapper removes it. Grass classification is also XZ-only for player, AI, and post-finish autopilot, allowing an elevated spur verge to change grip on another deck.

**Confirmed:** initial custom Test Drive carries `editorPreviewLayoutId`, but success/failure Retry carries only track ID. `startRace` treats the missing layout as null and rebuilds the authored course.

**Confirmed:** toolbar Delete ignores spur selection, while node or scenery selection does not clear an old spur selection. The shared handler prioritizes that retained spur point, and branch removal does not consistently reconcile active and selected spur indices.

<details><summary>Details</summary>

### High — Banked main/spur arbitration compares against centerline, not support mesh

Main-road edges include `bankHeight` at `components/modes/BaseMode.ts:742-747`. Deck arbitration compares `spurHeight` against centerline-derived `info.closestPt.y - 0.05` at `components/modes/BaseMode.ts:4361-4367`, but actual main support is later returned from banked edge interpolation at `components/modes/BaseMode.ts:4405-4411`.

**Confirmed:** a no-file probe used main support 2.4 m, an overlapping spur at 1.5 m, and `yHint = 2.4`. `getGroundHeight` returned 1.5 m; removing the spur made the same query return 2.4 m. Factor main support calculation into a candidate helper and compare that value before returning either deck.

### Medium — Opponent slope selection loses Y at the RaceMode boundary

`Vehicle.slopeSample` supplies `this.pos.y` at `components/objects/Vehicle.ts:2522-2525`, but the opponent binding at `components/modes/RaceMode.ts:333-336` accepts only X/Z and calls `this.getSlopeHeight(x, z)`. **Confirmed:** opponents therefore enter `BaseMode.getSlopeHeight`'s legacy no-hint XZ path at overlapping elevations, feeding the wrong deck into pitch, roll, and slope gravity. Forward the optional third argument and add a stacked-opponent regression.

### Medium — Spur grass classification crosses elevation levels

Player classification calls `getSpurInfo(x, z)` first at `components/modes/BaseMode.ts:476-484`; race classification repeats it at `components/modes/RaceMode.ts:383-390`; physics supplies only X/Z at `components/objects/Grass.ts:9`. **Confirmed:** a lower main-road car horizontally under elevated spur grass receives grass instability and speed loss, while spur asphalt can suppress main-road grass on another deck. Extend `Vehicle.isOnGrass` and `RacingAI.isOnGrass` with optional Y and pass it to both surface queries.

### Medium — Retry discards the selected raced branch

Initial Test Drive passes `editorPreviewLayoutId` at `components/Game.tsx:3011-3013`, and startup maps a missing layout to null at `components/Game.tsx:2056-2058`. `GameOverlays` exposes a one-argument callback at `components/ui/GameOverlays.tsx:28`; both Retry actions omit layout at `components/ui/GameOverlays.tsx:204-207` and `:239-242`. **Confirmed:** retrying Short rebuilds the unconverted authored track. Pass `activeLayoutId` into the overlay and preserve it on both paths.

### Medium — Spur selection and deletion use inconsistent state

Spur selection clears node/scenery state at `components/Game.tsx:3259-3265`, but node/scenery callbacks do not clear `selectedSpurPoint` at `components/Game.tsx:3267-3274`. Toolbar Delete ignores spur selection at `components/ui/MapEditor.tsx:549-552`, while its handler prioritizes a retained spur point at `components/Game.tsx:1194-1199`.

**Confirmed:** a spur-only selection disables Delete; selecting a node afterward enables the button but deletes the old spur point. Removing the last handle can remove its branch without clearing `activeSpurIndex`, while list deletion at `components/ui/MapEditor.tsx:1130-1134` clears active state but leaves point selection stale. Use one exclusive selection value, include spur selection in the gate, and reconcile both spur indices whenever a branch disappears.
