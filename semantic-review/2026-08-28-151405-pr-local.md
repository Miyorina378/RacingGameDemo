# Spur-road runtime fixes with incomplete editor selection cleanup

Change now compares stacked support against the actual banked road ribbon, carries vehicle elevation through slope and grass queries, preserves the active layout on Retry, and lets toolbar Delete act on a spur point. Those runtime and retry paths close the prior findings. Two editor paths still leave spur-point state inconsistent or omit it from generic selection commands. **Watch for:** **confirmed, Medium** double-click and Undo Point can leave stale active/selected spur indices; **confirmed, Low** Escape and Focus omit spur points.

**Verdict**: NEEDS_CHANGES

## High-level view

**Confirmed:** `getGroundHeight` compares the spur against interpolated banked mesh support, and `getSlopeHeight` follows that selected deck. Player, opponent AI, and post-finish autopilot grass paths forward vehicle Y, while success and failure Retry pass `activeLayoutId`.

**Confirmed, Medium:** only toolbar point deletion fully reconciles editor state. Double-click can remove a branch without updating `activeSpurIndex`, and Undo Point can remove the selected handle without updating `selectedSpurPoint`.

**Confirmed, Low:** Escape and Focus handle nodes and scenery but not the third selectable handle type. Escape retains a spur-point selection; Focus resets the view instead of flying to it.

### Point-removal paths leave stale spur identity

At `components/modes/PreviewMode.ts:949-958`, double-click calls `removeEditorSpurPointAt`, publishes the new array, and clears only the point selection. The helper removes a branch when its final handle disappears, but the React callback at `components/Game.tsx:3265-3271` changes `activeSpurIndex` only for a truthy selection. **Confirmed, Medium:** removing the final handle leaves the removed branch index active; a shifted branch can become active silently, or the index can point past the array. Reconcile `activeSpurIndex` against the returned array when branch count changes.

Preview selects each newly appended last handle at `components/modes/PreviewMode.ts:641-645`, while Undo Point slices off that same last handle at `components/ui/MapEditor.tsx:1321-1330` without changing `selectedSpurPoint`. **Confirmed, Medium:** the selection then points at a missing handle and toolbar Delete stays enabled for stale state. Route Undo Point through shared removal and clear or remap both indices atomically.

### Spur points fall outside Escape and Focus

The UI advertises “F fly to the selection” and “Esc deselect” at `components/ui/MapEditor.tsx:647-650`. Escape clears only node and scenery state at `components/Game.tsx:3173-3178`; Focus checks only those types before `resetView` at `components/modes/PreviewMode.ts:771-785`. **Confirmed, Low:** both commands behave incorrectly for a selected spur point. Clear it on Escape and resolve its authored position before Focus falls back to reset.
